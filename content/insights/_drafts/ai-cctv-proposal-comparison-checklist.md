**Straight answer: compare AI CCTV proposals by forcing every one of them into the same line-item template — software, processing hardware, setup, support, renewals, exclusions and acceptance criteria — and then converting each to a three-year total. Two proposals with the same headline number routinely buy different things; the template shows you what is missing before you sign rather than after.**

AI video analytics proposals are harder to compare than camera quotes, because the costs are spread across categories that suppliers bundle differently. One quotes software per camera per month and leaves hardware out. Another sells a box with "lifetime" software. A third quotes a site fee and treats tuning as an extra. None of these is wrong; they are just not comparable until you lay them side by side.

If you are still deciding which suppliers to ask, our guide to [what AI video analytics suppliers in India publish](/insights/compare-ai-video-analytics-suppliers-india) compares their public information. This article picks up once the proposals are on your desk.

## The five things every AI CCTV proposal must state

PGAK's own [pricing page](/pricing) groups costs the same way we suggest you group everyone's, including ours:

1. **Software** — which cameras, which analytics, the licence basis (per camera, per stream, per site), the term, and the renewal price.
2. **Processing hardware** — the device that runs the analytics, how many streams and which analytics it is sized for, who owns it, its warranty, and who replaces it if it fails.
3. **Setup and integration** — stream assessment, configuration, commissioning, and connection to your existing recorder or video management software.
4. **Support** — hours, response target, resolution target, updates, and what is excluded.
5. **Commercial terms** — taxes, payment schedule, pilot charges, termination, and how changes to scope are priced.

A proposal that is silent on any of the five has not told you its price yet.

## The comparison template

Copy this into a spreadsheet, one column per proposal. Fill every cell from the proposal document itself. If the document does not say, write **"not stated"** — that is information, and it becomes a question for the supplier.

| Line | What to record | Proposal A | Proposal B | Proposal C |
|---|---|---|---|---|
| **Scope** | Cameras covered (by name or location), analytics per camera | | | |
| Use cases | The events each analytic must detect, in one sentence each | | | |
| **Software licence** | Basis (per camera / stream / site), monthly or annual amount | | | |
| Licence term | Minimum term, lock-in, notice period | | | |
| Renewal | Renewal price or escalation rule after year one | | | |
| **Processing hardware** | Model, number of streams and analytics it is sized for | | | |
| Hardware ownership | Bought, rented or included; who owns it on exit | | | |
| Hardware failure | Warranty period; who replaces it and how fast | | | |
| **Cameras** | Reused, re-aimed, or replaced — listed per camera with reason | | | |
| Network and power | Switches, cabling, UPS, internet upgrades needed and priced | | | |
| **Setup** | Stream assessment, configuration, commissioning — priced or included | | | |
| Integration | Connection to existing recorder or VMS; what is supported | | | |
| Tuning period | Length, number of revisions, who does it | | | |
| Training | Who is trained, how long | | | |
| **Support** | Hours and days covered | | | |

| Updates | Software updates included; who schedules them | | | |

| **Exclusions** | Everything the proposal says it does not cover | | | |
| **Acceptance criteria** | Written test and pass conditions (see below) | | | |
| **Three-year total** | Sum of all one-time and recurring lines, ex-GST | | | |

Two rows deserve particular attention.

**Processing hardware.** Analytics has to run somewhere: on the camera, on a box on site, or in a cloud service. Where it runs changes the hardware cost, the internet requirement and what happens during an outage. PGAK runs detection on an on-site processing unit, and every proposal — ours included — should say what that unit is, what it is sized for, and who replaces it. The [edge AI calculator](/features/guides/edge-ai#scenario-C05) compares on-site processing with cloud processing using your own camera count and stream settings, and the [bandwidth and cloud cost calculator](/calculators/bandwidth-and-cloud-cost) shows what sending video off-site would cost in upload and storage.

**Exclusions.** The most expensive surprises live here: a camera that needs replacing after all, a network switch that cannot carry the extra load, configuration changes after go-live charged by the visit. Ask each supplier to list exclusions in writing. A proposal with no exclusions listed has not finished being written.

## A worked example: normalising three proposals

*Illustrative example. The suppliers and every figure below are hypothetical, chosen as round numbers to show the arithmetic. They are not PGAK prices or anyone else's.*

A factory asks three suppliers to cover the same eight cameras.

| | Proposal A | Proposal B | Proposal C |
|---|---|---|---|
| Software | ₹2,000 a month for all eight cameras | Included for three years | ₹30,000 a year |
| Processing hardware | ₹60,000 one-time | ₹1,50,000 one-time (box with software) | "Not stated" |
| Setup and tuning | ₹20,000 | Included | ₹25,000 |
| Support | Included in software | ₹15,000 a year from year two | ₹10,000 a year |
| Renewal after year one | Same | Software renewal "at prevailing rates" after year three | 10% a year |

Three-year totals, ex-GST:

- **Proposal A:** ₹60,000 + ₹20,000 + (₹2,000 × 36 months = ₹72,000) = **₹1,52,000**
- **Proposal B:** ₹1,50,000 + (₹15,000 × 2 years = ₹30,000) = **₹1,80,000**
- **Proposal C:** ₹25,000 + software (₹30,000 + ₹33,000 + ₹36,300 = ₹99,300) + support (₹10,000 × 3 = ₹30,000) = **₹1,54,300 — plus processing hardware, not stated**

On headline numbers, C looked cheapest because its first-year software line was smallest. Normalised, A and C are close, and C has a hole where the hardware should be. B is highest over three years, but includes the hardware outright; what matters is what B costs from year four, which it has left open. Each proposal now produces a specific question rather than a vague preference.

## Writing acceptance criteria before you sign

A proposal that says "AI detection of intruders" has not told you how you will know it works. Agree acceptance criteria in writing, before installation, using the same definitions for every supplier. Our [pilot evaluation worksheet](/resources/evaluation-method) gives the full method; the short version:

- **The event**, in one sentence: "a person enters the closed loading bay after 10 pm".
- **The cameras and hours** the test covers.
- **The log**: a person records real events independently, so true, false and missed alerts can be counted. Model confidence on screen is not accuracy.
- **Delivery**: alerts reach the named phones; the delay is recorded with synchronised clocks.
- **Interruption**: what happens when a camera stream drops, the processing unit restarts, the power fails or the internet is down. The [deployment requirements page](/platform/deployment) lists these tests.
- **The pass condition**, agreed before the test starts. Do not set the threshold after seeing the results.
- **What happens if it fails**: revise and retest, or stop — and what that costs.

## Red flags in an AI CCTV proposal

- A single bundled price with no breakdown.
- Accuracy percentages with no site, period or method behind them.
- "Works with any camera", or compatibility claimed from the brand name alone. Compatibility depends on the model, firmware and stream; our [compatibility page](/platform/compatibility) explains the check.
- "No new hardware needed" with no explanation of where the analytics runs.
- Renewal "at prevailing rates" with no cap.
- No exit terms: what happens to your data and the hardware if you stop.

## When the template says "do not buy yet"

Sometimes the normalised table shows that no proposal does what you needed, or that all of them depend on replacing cameras you thought were fine. That is a useful result. It may mean the use case needs rethinking, the cameras need a survey first, or a simpler fix — better lighting, a guard schedule, a maintained recorder — covers the risk for less. A procurement template is meant to make that visible, not to force a purchase.

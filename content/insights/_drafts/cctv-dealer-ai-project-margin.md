**Straight answer: an AI analytics project's delivery margin is what is left after you subtract the hardware you buy, every site day, the tuning period, the support time that follows go-live, and the cost of waiting to be paid — from everything you invoice. Camera dealers often underestimate it because most of the work on a camera job ends at handover, while on an analytics job a real share of it starts there. Work it out with your own numbers before you quote, not after.**

Many CCTV dealers and installers in Punjab are being asked by customers about "AI cameras" and analytics. Some suppliers invite dealers to resell or refer. Before taking on that work, it is worth knowing what one project actually earns you.

One thing to be clear about first: **PGAK does not publish a partner margin, discount or commission**, and nothing in this article implies one. Our [partners page](/partners) handles dealer and integrator enquiries separately from customer sales, and says plainly that no appointment, territory or commercial arrangement is implied by an enquiry. This worksheet is for your own numbers, whichever supplier you work with.

## Why an analytics job is a different kind of job

On a camera installation, the work is front-loaded: survey, supply, install, commission, hand over, collect. After that, maintenance is usually a separate contract.

On an analytics project, several pieces of work continue after handover:

- **Stream checks.** Existing cameras and recorders have to provide a usable stream, and some will not. Finding out costs a site visit even when the answer is no. The [ONVIF integration guide](/features/guides/onvif-integration) explains what is being checked.
- **Re-aiming.** A camera positioned for general recording is often wrong for detection — too high, too wide, facing the light. Moving it is unbilled time unless you price it.
- **Tuning.** Detection zones, schedules and alert recipients need adjustment against real activity for the first few weeks. Someone has to do it.
- **The first phone call.** When an alert does not arrive, the customer rings whoever they know — usually you.
- **Collections.** The project is often invoiced in stages, and the last stage is tied to acceptance, which depends on tuning.

None of this makes analytics a bad line of business. It makes it a different one, and it needs pricing that way.

## The delivery margin worksheet

Fill this in for one real project you are quoting. Use your own costs, not a supplier's estimate of them.

### Part A — what you invoice the customer

| Line | Your figure (₹) |
|---|---|
| A1. Hardware you supply (cameras, switches, UPS, cabling) | |
| A2. Installation and commissioning labour | |
| A3. Analytics software or licences, **if you invoice them** (leave blank if the supplier invoices the customer directly) | |
| A4. Processing hardware, **if you invoice it** | |
| A5. Tuning or configuration charge, if separately billed | |
| A6. First-year support or AMC you will invoice | |
| **A. Total invoiced (ex-GST)** | |

### Part B — what the project costs you

| Line | How to calculate | Your figure (₹) |
|---|---|---|
| B1. Hardware cost | Your purchase price for everything in A1 (and A4 if you supply it) | |
| B2. Software or licence cost | What you pay the supplier for A3, if anything | |
| B3. Survey and stream-check visits | Visits × technician day cost | |
| B4. Installation days | Technician days × day cost, including helpers | |
| B5. Re-aiming and revisits | Expected extra visits × day cost | |
| B6. Tuning time | Hours over the tuning period × hourly cost | |
| B7. Travel | Trips × cost per trip (fuel, vehicle, time) | |
| B8. First-year support time | Expected calls per month × hours per call × hourly cost × 12, plus any site visits | |
| B9. Warranty swaps | Expected failures × (your handling time; parts if not covered) | |
| B10. Cost of waiting to be paid | Amount outstanding × your monthly cost of money × months outstanding | |
| B11. Allowance for non-payment | A percentage you set from your own history | |
| **B. Total cost** | | |

### Part C — the answer

- **Delivery margin (₹)** = A − B
- **Delivery margin (%)** = (A − B) ÷ A × 100
- **Margin per technician day** = (A − B) ÷ (total days in B3, B4, B5 and the day-equivalent of B6 and B8)

The last figure is often the most honest. It tells you whether this project earns more or less per day of your team's time than an ordinary camera job — which is the real alternative use of that time.

## A worked example

*Illustrative example. Every figure is hypothetical and rounded to show the arithmetic. It is not a PGAK price, margin or term, and it is not typical of any market.*

A dealer quotes a factory for analytics on eight existing cameras, two new cameras, a UPS and a network switch. The software supplier invoices the customer directly for software and processing hardware, so the dealer invoices only hardware, labour, tuning and support.

**Invoiced (A):** hardware ₹60,000 + installation ₹20,000 + tuning ₹10,000 + first-year support ₹15,000 = **₹1,05,000**

**Costs (B):**

- Hardware cost: ₹45,000
- Survey and stream check: 1 day × ₹3,000 = ₹3,000
- Installation: 3 days × ₹3,000 = ₹9,000
- Re-aiming revisits: 2 days × ₹3,000 = ₹6,000
- Tuning: 12 hours × ₹400 = ₹4,800
- Travel: 8 trips × ₹500 = ₹4,000
- Support: 2 calls a month × 1 hour × ₹400 × 12 = ₹9,600, plus 2 visits × ₹3,000 = ₹6,000 → ₹15,600
- Waiting to be paid: ₹40,000 outstanding × 1.5% a month × 3 months = ₹1,800
- Non-payment allowance: 2% of ₹1,05,000 = ₹2,100

**Total cost: ₹91,300**

**Delivery margin:** ₹1,05,000 − ₹91,300 = **₹13,700**, or about **13%**.

**Days of team time:** 1 + 3 + 2 survey/install/revisit days, plus tuning (12 hours ≈ 1.5 days) and support (12 hours ≈ 1.5 days, plus 2 visits) ≈ **11 days** → about **₹1,250 per day**.

On the hardware alone, the dealer appeared to make ₹15,000 (₹60,000 − ₹45,000) plus labour. The worksheet shows that revisits, tuning and support absorbed most of the labour income. In this hypothetical case, the dealer's options are to price tuning and support realistically, cut revisits through a better survey, or agree that the software supplier handles tuning remotely.

## The responsibility split to agree before the first sale

Most margin disputes between dealers, suppliers and customers come from work nobody was assigned. Agree this table in writing with any analytics supplier before you quote a customer:

| Responsibility | Dealer | Software supplier | Customer | Notes |
|---|---|---|---|---|
| Site survey and stream check | | | | |
| Cameras, cabling, power, network | | | | |
| Processing hardware supply | | | | |
| Processing hardware failure and replacement | | | | |
| Analytics configuration | | | | |
| Tuning period (who, how long) | | | | |
| First-line support (customer's first call) | | | | |
| Second-line support (software faults) | | | | |
| Software updates | | | | |
| Recorder and camera passwords | | | | Customer should hold admin |
| Customer data and footage | | | | Never shared in a sales enquiry |
| Invoicing and collection for each line | | | | |
| Acceptance test and sign-off | | | | |

Two lines cause the most trouble. **First-line support:** if you take the customer's first call, price it. **Processing hardware failure:** decide who diagnoses it, who ships a replacement, and who visits — and how fast.

## When this work is not worth taking

The worksheet will sometimes give a margin per day below what your team earns on ordinary installations. That can still be worth it if it wins you the camera business, the AMC, or a customer you want. It is not worth it if every analytics project needs three revisits and an unpaid month of tuning.

It is also not worth taking a project where the customer's cameras clearly cannot do the job and the customer will not pay to fix them. The [retrofit versus replacement calculator](/calculators/retrofit-vs-replacement) and the [ONVIF integration calculator](/features/guides/onvif-integration#scenario-C24) help you show a customer, with their own figures, what keeping or replacing their cameras would cost.

## A note on customer data

When you discuss a project with any supplier, do not send customer contact lists, recorder passwords, stream addresses or footage in an enquiry, by WhatsApp, or through a web form. A supplier who needs stream access should arrange it with the customer's authorisation at the assessment.
